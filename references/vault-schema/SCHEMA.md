# SCHEMA — Hephaestus

> **Canonical kit asset.** Lives only inside Hephaestus (`references/vault-schema/` +
> `catalog/routing-defaults.json`). The external legacy vault-asset package was absorbed on
> 2026-08-12 (trail `HEPHAESTUS_V1`, Plan 01) and **discarded** — do not consult, mirror, or
> depend on any source outside the kit. Rules from §2, §4, §5, §7 and §8 are preserved; public
> vocabulary follows the Hephaestus standard.

Operational reference for the vault skills. Contains the **what**; the **why** lives in the SPEC.

The project `AGENTS.md` **does not** cite this file: it contains only the immutable anchors of
the vault and the process. The read/write protocol arrives via the global instruction (in Hephaestus,
the product and process sections of `AGENTS.md` are content generated by running `/hephaestus`).

---

## 1. Single principle

> **The vault contains only what is true today.**

Process document — how the rule was reached, what was intended, how it was executed — does not
live in the vault. It lives in `.app-work/`.

---

## 2. The two territories — closed list

A folder outside this list **does not exist** for the framework: it gets no index, does not enter
the skill, is not created by the agent.

```text
_app-vault/                 # CURRENT TRUTH — visible, searchable
  INDEX.md                  # live map (§3)
  docs/
    decisions/              # SOURCE OF TRUTH — one file per domain (§4)
    TEMPLATES/              # uppercase, mandatory
  specs/                    # technical specs (backend, API contract)

.app-work/                  # PROCESS — disposable, hidden from search
  INDEX.md                  # process map (§8) — pointer, not content; AGENTS.md anchor
  .gitignore                # versioned; contains `references/` and `private/`; `issues/` if the repo is public (D43)
  hephaestus-state.json     # versioned kit state (lowercase)
  guides/<NAME>_GUIDE/
  guides/legados/
  roadmap/                 # ROADMAP.md + slices/ — versioned
  brainstorming/<topic>/
  prd/
  docs/                    # live; omit if empty
  issues/
  references/              # gitignored — sole place for OSS clones
  private/                 # auditorias/, ops/, research/, notes/ — gitignored
  archive/
    guides/<YYYY-MM>/semana-<N>/<NAME>_GUIDE/
    perguntas/<topic>/
    prds/
    roadmap/<MILESTONE>_<YYYY-MM>/
    docs/ backlogs/ plans/ sprints/ features/ design-prototipos/
    produto/ qa/ releases/ evidence/ issues/<YYYY>/
```

**Every folder under `_app-vault/` is current.** Without exception: what aged out leaves the vault — that
is what removed `archive/` and `_private/` from there. What remains is current by construction, not by
vigilance.

**Presence under the vault root is not canonical format.** Path `_app-vault/docs/features/`,
`docs/platform/`, `DECISIONS_*` outside `docs/decisions/`, etc. is **outside** this list: on
adoption (`/hephaestus` mode `adopt`) and on the `maintain` integrity check, such material is
**reclassified** (decision → `docs/decisions/` as `### DEC-NNN`; technical spec → `specs/`;
process/shell → `.app-work/`). No-touch (byte-for-byte copy) only applies to paths **already** listed
above in the right format — see `prompts/route.md` level 1 and DEC-004.

The vault is not mirrored outside the project.

### 2.1 Boundary

| Folder | Role | Source of truth? |
|---|---|---|
| `_app-vault/docs/decisions/` | Current rule by domain | **Yes — the only one** |
| `_app-vault/docs/TEMPLATES/` | Templates | No |
| `_app-vault/specs/` | Technical specification | No |
| `.app-work/**` (everything, including `private/` and `archive/`) | Process | **Never — forbidden as input** |

**Reference is one-way.** Guide → decision always; decision → guide never. A file in
`docs/decisions/` that needs to point to a guide indicates an unpromoted rule: promote (§6), do not
reference.

**`references/` is the worst possible input.** It carries quotas and contracts from *another* project; an
accidental match there is indistinguishable from your own rule. The ignore travels with the schema:
versioned `.app-work/.gitignore`, not a loose line in the root `.gitignore`. The same file ignores
`private/`.

### 2.2 Cycles

- **Guide** — born in `.app-work/guides/`, executed, goes to the dated **mirror**:
  `.app-work/archive/guides/<YYYY-MM>/semana-<N>/<NAME>_GUIDE/` (DEC-002). An already-dated path is
  canonical (no-touch); legacy under `.app-work/done/` and flat `archive/guides/<PACK>/` migrate on the
  next run. Monolithic still cited without a pack: `guides/legados/`. Never consulted in
  feature, infrastructure, or architecture analysis.
- **Brainstorm** — on close, it routes and does not remain as a live reference: product →
  `_app-vault/docs/decisions/`; architecture/implementation → `project-rules/`; the closed notebook goes
  to the mirror `archive/perguntas/<topic>/` (DEC-002).
- **PRD** — dated proposal, not always fulfilled in full. Not a contract. Retired → the
  mirror `archive/prds/` (DEC-002).
- **Roadmap** — live in `.app-work/roadmap/` (`ROADMAP.md` + slices), versioned, sole promotion
  queue; never in `private/`. Closed milestone → `archive/roadmap/<MILESTONE>_<YYYY-MM>/`.
- **Docs** — live in `.app-work/docs/` (omit if empty); retired → `archive/docs/`.
- **Archive** — mirror of completed items + named deposit (not "any folder"). Mirror: `guides/<YYYY-MM>/semana-<N>/`,
  `perguntas/`, `prds/`, `roadmap/<MILESTONE>_<YYYY-MM>/`. Fixed-name deposit: `docs/`, `backlogs/`,
  `plans/`, `sprints/`, `features/`, `design-prototipos/`, `produto/`, `qa/`, `releases/`,
  `evidence/`, `issues/<YYYY>/`. No schema rule depends on what is there.
- **Private** — private gitignored area: `auditorias/`, `ops/`, `research/`, `notes/`. Not a home
  for roadmaps. Never pushed to the remote. Like all of `.app-work/`, forbidden as rule input.
- **Issues (D43)** — sole record of defects and UI/UX/behavior adjustments: a line in the
  folder's `INDEX.md` (live table by state — Open / In verification / Closed) with a sequential
  `ISSUE-NNN` ID (unique prefix across all projects), severity S0–S3 and cycle
  `OPEN → FIXED → VERIFIED → CLOSED` (+ WONTFIX/DUPLICATE); rich context (evidence, technical
  notes) lives in an **optional** sibling `ISSUE-NNN.md`. **Visibility:** a **private** repo
  versions `issues/` (traceability + collaboration); a **public** repo ignores it via
  `.app-work/.gitignore` (the `issues/` line) — an issue carries internal context (evidence, PII,
  premature decisions) and public git is immutable. Decided by an adoption question with `reason:
  issues-visibility` (queued by `discover`, one per project, non-blocking), with the answer
  persisted in the `answers` block of `.app-work/hephaestus-state.json` (`scope: this-project`,
  `answer.issuesVisibility: versioned | gitignored`) and consumed by `compose` when materializing
  `.app-work/.gitignore`, binding by `questionKey` + `contextFingerprint` in `adopt` and
  `maintain`; without an answer, the declared conservative default applies: ignore `issues/` + a pending
  item in closeout — the kit never infers public/private. One-path rule;
  in a public repo the record is local-only (external collaboration, if ever, via GitHub Issues).

### 2.3 Prefixes and naming

The prefix is a **search-visibility switch**, not cosmetic. Verified on ripgrep 15.1.0:

| Command | Dotfolder files seen |
|---|---|
| `rg --files` (from root) | **0** |
| `rg --files --hidden` (from root) | **260** |
| `rg "x" .app-work/…` (path cited) | **works, no flag** |

`.` blocks implicit traversal, not access — plain `grep -r` enters dotfolders. Partial defense,
not airtight.

- `docs/TEMPLATES/` **uppercase** (lowercase passes on macOS and breaks on Linux/CI).
- Guides: `.app-work/guides/<NAME>_GUIDE/`, `<NAME>` in `UPPERCASE_WITH_UNDERSCORE`.
  Executed: `.app-work/archive/guides/<YYYY-MM>/semana-<N>/<NAME>_GUIDE/` (DEC-002).
- Decisions: `docs/decisions/<domain>.md`, kebab-case.
- Framework trigger: `_app-vault/INDEX.md` exists. Without it, the agent **does not** create the vault.

### 2.4 Routing defaults (D42)

Legacy → canonical classification (adoption **and** maintenance) uses `catalog/routing-defaults.json`
(at the Hephaestus kit root). It is a **live** asset: `high`-confidence lines avoid re-asking;
new answers to ambiguous classification become candidates and only enter the table after explicit
promotion at the D42 gate — the adoption handoff (`/hephaestus` mode `adopt`) **or** end of fix /
routing modality of `maintain` mode (`/hephaestus`). LLM record, classification, or decision never
replaces human confirmation when the change is destructive. An illegal destination (outside §2) is
refused.
See the procedure in the Hephaestus pipeline phases.

## 3. `INDEX.md`

Pointer, not content. Model: `INDEX_TEMPLATE.md`.

- Mandatory frontmatter: `vault_version`, `updated`, `scope`.
- `## Domains` — one pointer per file in `docs/decisions/`.
- `## By feature` — reverse index **derived** from the `Affects:` fields, never hand-written.
  Preceded by the list of valid features.
- Cap **~100 lines**. Past that → the index became content; refactor.
- **Never enters:** current decision value; **any pointer to `.app-work/`**; plan/task listing;
  PRD or spec copy.

The process map is not this file: it is `.app-work/INDEX.md` (§8). The "never enters" rule here applies
to the vault index; the process has its own index — anchored by `AGENTS.md`, never as rule
input.

## 4. `docs/decisions/<domain>.md`

Model: `DECISION_TEMPLATE.md`.

### 4.1 Semantics (do not regress)

- One file per **product domain** — an area the end user recognizes
  (`planos-e-cotas.md`, `autenticacao.md`, `pagamentos.md`).
- **Not** by feature, screen, sprint, or date. **Not** one file per dated decision.
- **There is no decision superseded by another decision.** A decision is born, lives, and is **changed
  in place**: the value changes, the `DEC-NNN` stays. Removal is possible but rare.

### 4.2 `DEC-NNN` is the rule anchor

Each rule has its own heading, with the ID attached to the statement:

```markdown
### DEC-016 — Free-plan export quota

Free plan: 20 exports/mo.
```

The ID identifies the **current rule**: stable, immortal, citable from outside. Anchoring the whole file
is not acceptable — a domain holds 5–10 rules and "per DEC-016" would not say which.

A rule's identity is semantic and independent of the variable value: domain, subject/object,
condition or scope, and rule type form the match key. Limit, number, enumeration, and other
values are payload; when only the payload changes, the same `DEC-NNN` is changed in place. Textual
similarity only breaks ties between clauses that already share the same identity; ambiguous identity
requires human confirmation.

### 4.3 File structure

```markdown
# <Domain>

Affects: [login, billing, dashboard]

### DEC-016 — Free-plan export quota

Free plan: 20 exports/mo.

_Changed 2026-08-05 — was: 10/mo. Reason: pilot feedback._

### DEC-021 — Annual-plan courtesy

Annual plan includes 2 courtesy months.
```

`Affects:` goes right after the title, above the first clause. Features in kebab-case. It is the input
to `## By feature`.

### 4.4 Change trail — inline note

A clause change records **one line**, right below the statement:

```markdown
_Changed <date> — was: <old>. Reason: <reason>._
```

- The ID is **not** repeated: it is already in the heading.
- New notes stack **above** the previous one (most recent first).
- Past **~3 notes** on the same clause, the old ones are **deleted**. The current statement and
  recent notes stay. They do not go to `archive/` — the archive has no task or format.

The note dies with the rule: once the clause is removed, the trail is gone and no orphan line remains.

### 4.5 Removal — the only exception

Without a clause there is nowhere to hang the note. Only then does the file gain a trailing `## History`,
one line per removal:

```markdown
## History

- 2026-08-05 — DEC-009 removed. Was: cap of 3 projects on the free plan. Reason: limit abolished.
```

The ID cited here **must not** exist as a clause above — if it exists, it was not removed.

`## History` stays in the live file and **never** goes to `archive/`: it is what keeps a removed
rule's ID visible to the numbering inventory (§4.7).

Before removing, search for pending citations of the ID (§4.7).

### 4.6 Source of truth

- **Only** `docs/decisions/` determines the current rule.
- `specs/` is context, never rule input.
- All of `.app-work/` is **forbidden** as input.
- A rule cited only in a guide/brainstorm/PRD and missing from `docs/decisions/` **is not a rule** — it is a
  gap to promote (§6).

### 4.7 Numbering and integrity

- Sequential **per project**: `max(existing) + 1`, computed **only** over `docs/decisions/` —
  live clauses **and** IDs listed in `## History`. It does not depend on `archive/`: no ID lives
  only there, so deleting the archive does not reopen number reuse.
- **Never reuse** a number, including from a removed decision.
- **Never number by domain** (`DEC-PAG-001`).
- On adoption, inventory the largest existing ID before minting the first new one. A greenfield project starts
  at `DEC-001`.
- **Dangling reference:** immortal ID + permitted removal means an external citation may outlive the rule.
  On removal, search for citations of the ID — including in `.app-work/`, which requires `--hidden` or a
  cited path — and report them.

### 4.8 Split and domain creation

Split only when the file became hard to read **or** two blocks are never consulted together.

A new rule with no obvious domain: **extend** if it concerns the same end-user-recognized product
that already has a file; **create** only if no existing file houses it; **when in doubt, extend**.

## 5. Decision writing — the four modes

Writing is **minimal**: only a decision when the task **changes** product or contract. Identify the mode
before acting. **When in doubt between §5.1 and §5.3, treat as §5.1.**

### 5.1 Replacement — contradicts a current rule

Emit, **before** applying:

```text
⚠️ Previous product decision: <old value>
   Source: <file:line>
   Current request: <new value>
   Also affected: <what else depends on this value>
   Confirm the new rule?
```

- **Confirmed** → change the statement under the existing `DEC-NNN` (**the ID does not change**), add the
  inline note (§4.4), and keep executing the request in the same flow.
- **Denied** → do not apply.

`Also affected` is not decoration: a limit often has a neighboring rule hanging off it.

### 5.2 Does not escalate to the STOP protocol

- **Project / implementation rule** → STOP + UPPERCASE of the global `AGENTS.md`.
- **Product / contract rule** → the §5.1 alert, same conversation.

### 5.3 Clause addition

A request introducing an option, benefit, condition, or exception **without** removing or changing any
existing value:

1. Does not trigger an alert.
2. Takes no inline note.
3. **Is** a decision: create a new clause with a new `DEC-NNN` (§4.7).
4. Introduced a **new domain** or a **new `Affects:` tag** → update `INDEX.md` in the same flow:
   `## Domains`, the valid-feature list, and `## By feature` (§3, §7).

Without step 3, "no conflict → nothing to write" becomes silent drift. Without step 4, the index stays
divergent until the next maintenance run (`/hephaestus` mode `maintain`).

### 5.4 Cross-domain

When the scope reaches another domain, the write is not atomic to a single file:

1. Update all affected domains.
2. Cite the **sibling `DEC-NNN`** in the note of each touched file. E.g.:
   `_Changed 2026-08-05 — was: R$ 99/yr. Reason: price adjustment; see DEC-024 in pagamentos.md._`
3. Update `Affects:` and `## By feature` if the scope changed.

### 5.5 Removal

See §4.5. Rare. Requires a pending-citation check and a `## History` line.

## 6. Promotion to decision

Prevents "rule living only in a guide". Since `.app-work/` is invisible to search, **what is not promoted
is effectively lost**.

**Strong trigger (deterministic) — must promote** when the request changes, in an already-existing rule:
value/limit/floor/ceiling; enumeration item or plan option; product-contract field.

**Weak trigger (heuristic) — consider** when facing: norm language ("always", "never",
"default", "from now on"); an effect observable by the end user; scope beyond the current
guide.

**Does not promote:** a choice with no observable effect — file name, refactor order, test
strategy, internal detail.

**Backstop:** on closing a plan or guide, the executor records `Decision candidates` in the pack's `LEDGER.md`,
with the rule text and where it was cited. `/hephaestus` `maintain` mode presents a batch
promotion question with `candidateId`, origin, evidence, `questionKey`, and
`contextFingerprint`. The candidate is not `reconcile` input until an explicit human answer
with `confirmed: true`, `statement`, and `domain`; that answer preserves origin as context only.
Backstop is a safety net, not the main path.

## 7. Feature tags

- **One feature = one stable kebab-case slug.** Do not version in the slug (`login-v2` is a new slug and
  breaks the reverse index).
- **Controlled vocabulary.** Valid-feature list declared once in `INDEX.md`, above
  `## By feature`. Tag outside the list → add to the list or refuse the tag.
- **Cross-cutting case** (security, logging, i18n, privacy): the decision lives in its own domain
  and is tagged on every feature it touches. There is no "cross-cutting" domain of pointers only.
- **Derivation, not free writing.** On divergence, `Affects:` is the truth and `INDEX.md` is corrected.
  Derivation runs **at write time** (§5.3 step 4), not only in the maintenance sweep
  (`/hephaestus` mode `maintain`).

## 8. The three regimes

| Regime | Home | Content |
|---|---|---|
| **Product** | `_app-vault/` | decision, current rule, product contract |
| **Code** | `project-rules/` | implementation norms for coding |
| **Process** | `.app-work/` | guide, brainstorm, PRD, references, issues — disposable |

Adoption does not merge the three. The project `AGENTS.md` receives the Hephaestus-generated product and
process anchors: `_app-vault/INDEX.md` (product/decision) and `.app-work/INDEX.md`
(process). Anchoring means pointing at the **map** — `.app-work/` stays forbidden as rule input:
the anchor exists so the LLM finds the organization map, not to consult process content.

**Hybrid case** (~15% of rules): the **end-user-observable effect** goes to
`docs/decisions/`; the **how-to-implement norm** goes to `project-rules/`. Duplicating the literal
value is forbidden — `project-rules/` **references** the `DEC-NNN`, not copies the value.
